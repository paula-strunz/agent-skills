# Output Quality Gate

Run these checks against any artifact generated by the dev-lifecycle skill before considering it complete.

## Content Quality

- [ ] Every sentence carries information (no filler, no fluff)
- [ ] No em dash characters used anywhere
- [ ] No "is not X, is Y" constructions
- [ ] No ChatGPT filler phrases ("it's worth noting", "importantly", "leverage", "delve into")
- [ ] Output reads like a senior engineer wrote it
- [ ] Concise but still clear to someone reading for the first time

## Structural Quality

- [ ] Output follows the cookbook's specified template or format
- [ ] All required sections are present
- [ ] No placeholder text left unfilled (unless explicitly marked as TBD)
- [ ] File saved to the correct path per Save Path Convention or project-specific routing

## Project Relevance

- [ ] References actual file paths, modules, or components from the codebase (not generic placeholders)
- [ ] Aligned with project conventions discovered from project guidance files and repository structure
- [ ] No hardcoded references to other projects

## For Iterative Consultation Outputs

- [ ] Scratchpad updated after each user response
- [ ] All major aspects explored before generating final document
- [ ] User confirmed before final document generation
- [ ] Final document saved to correct core_docs path
